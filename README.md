# LocalPad

A personal notepad inspired by Dontpad, **local** and **offline-first**.
Open any URL (`/meeting`, `/todo`, `/work/ideas`) and start writing: content is saved automatically to the browser's IndexedDB and never leaves the device.

## Running

```bash
npm install
npm run dev       # development (http://localhost:5173)
npm run build     # type-check + production build in dist/ (includes the service worker)
npm run preview   # serve the build locally (test offline/PWA here)
npm test          # data-layer tests (Vitest + fake-indexeddb)
```

The service worker is only generated by the build. To test offline mode and PWA installation, use `npm run build && npm run preview`.

## How it works

| Route | Behavior |
| --- | --- |
| `/` | List, search (by slug and content), delete, export and import |
| `/<slug>` | Opens the document, or creates an empty one if it doesn't exist |

- **Slugs** are normalized: lowercase, spaces become `-`, extra slashes are removed. `/Project Ideas/` → `/project-ideas`. Inner slashes are allowed (`/work/meeting`).
- **Autosave** runs 400 ms after you stop typing, and also when switching tabs, closing the page or navigating away. The indicator shows *Editing… / Saving… / Saved / Save failed* (on failure it retries every 3 s).
- **Multiple tabs**: the same page open in two tabs stays in sync (Dexie `liveQuery`). Unsaved local edits take priority.
- **Persistence**: the app calls `navigator.storage.persist()` to reduce the chance of the browser evicting the data.
- **App updates** appear as a notice ("A new version is available") instead of reloading in the middle of typing.

### Backup

*Export JSON* produces `localpad-backup-YYYY-MM-DD.json`:

```json
{ "format": "localpad-backup", "version": 1, "exportedAt": 0, "documents": [ /* Document[] */ ] }
```

*Import JSON* merges by slug: new slugs are added; existing slugs are replaced only if the imported version is **newer** (`updatedAt`). Nothing newer on the device is overwritten.

## Structure

```
src/
  lib/db.ts            Dexie schema (documents table: id, &slug, updatedAt)
  lib/documents.ts     getOrCreate / save / delete / list
  lib/backup.ts        Export, validation and import
  lib/slug.ts          Slug normalization
  lib/router.tsx       Minimal History API router (base-path aware)
  pages/HomePage.tsx   List, search and backup
  pages/EditorPage.tsx Editor with autosave
scripts/generate-icons.mjs  Generates the PWA PNG icons (npm run icons)
scripts/spa-fallback.mjs    Copies index.html to 404.html during the build
```

## Deploy (GitHub Pages)

1. Push the repository to GitHub.
2. In **Settings → Pages → Build and deployment**, set **Source: GitHub Actions**.
3. Every push to `main` runs `.github/workflows/deploy.yml`: tests, build and publish.

The workflow detects the base path automatically:

| Site type | URL | `BASE_PATH` |
| --- | --- | --- |
| Project site | `https://<user>.github.io/<repo>/meeting` | `/<repo>/` |
| User site or custom domain | `https://<domain>/meeting` | `/` |

To test the project-site setup locally: `BASE_PATH=/localpad/ npm run build && npx vite preview --base /localpad/`.

**Routing:** GitHub Pages doesn't rewrite URLs, so the build copies `index.html` to `404.html`
(`scripts/spa-fallback.mjs`). The first time `/meeting` is opened, Pages serves that file with
HTTP status 404, but the app loads normally and opens the document. Once the service worker is
installed, every route is served from the cache with status 200, including offline.
See [ADR 0001](docs/adr/0001-path-routing-on-github-pages.md) for the options considered and trade-offs.

## Limitations (by design)

- Documents are isolated per browser, profile and origin. The same URL on another device is a different document.
- Sharing a URL does not share its content.
- Clearing site data deletes the documents. Use the backup.
